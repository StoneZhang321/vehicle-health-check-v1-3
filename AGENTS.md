# Development rules

- Keep domain rules and local persistence separate from UI. Plan cross-module changes first.
- Use one writer per file and concise Chinese/English comments for major behavior.
- Preserve professional content versions and scoring unless intentionally researched and changed.
- Keep reports immutable and attachment identity positional.
- Run relevant type, lint, build and behavior checks; avoid redundant test matrices.
- Independently review changed structure and actual user journeys.
- Installation, development and build must never deploy. Deploy explicitly to your own account and target.
- Never commit credentials or real vehicle records.
